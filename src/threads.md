# Потоки

Скрипт идёт на том потоке, который его вызвал. Почти всё работает на основном потоке игры: события, рисование, окна, HUD. На других потоках работают только:

- хуки, если игра вызвала метод на другом потоке (как у Mixin);
- события `net_receive` и `net_send`.

## Пакеты на сетевом потоке

```lua
local m = strix.module("NoTime", { category = "Misc" })
local dropped = 0

m:on("net_receive", function(packet)
    if java.instanceof(packet, "net.minecraft.network.protocol.game.ClientboundSetTimePacket") then
        dropped += 1
        return true -- игра не увидит пакет
    end
end)
```

`net_receive` получает входящий пакет сразу при приходе, до того как игра его обработает. Если хотя бы один модуль вернул `true`, пакет отменён, а модули с `packet_cancelled` об этом узнают. `packet_received` приходит только для неотменённых пакетов.

`net_send` получает пакеты, отправленные не с основного потока: например, ответы на keep-alive. Отправленные с основного идут в `packet_send`.

Оба события видят все соединения клиента, а не только игровое: например, опрос серверов в списке (`ServerboundStatusRequestPacket`), а в одиночной игре и серверную сторону встроенного сервера. Проверяй тип пакета через `java.instanceof`, прежде чем его отменять.

## Что можно на сетевом потоке

| Можно | Нельзя |
|---|---|
| Читать пакет и менять его через [мост](java.md) | `strix.inventory`, `strix.rotations`, `strix.combat`, `strix.chat`, `strix.toast` и другие сервисы: они дают ошибку |
| `print`, `strix.log.*` | Читать и менять игрока, мир и сущности: это гонка с основным потоком, и мост её не отследит |
| Читать настройки, `s:set(v)` (применится на ближайшем тике) | Ждать основной поток: `future:get()`, `executeBlocking` могут завесить игру |
| `strix.net.send`, `strix.main` | |

## Возврат на основной поток

`strix.main(f)` выполнит функцию на основном потоке в ближайший тик, там снова доступны игрок, мир и все сервисы. `strix.is_main()` → `boolean` говорит, где идёт код.

```lua
local m = strix.module("TimeLog", { category = "Misc" })

m:on("net_receive", function(packet)
    if java.instanceof(packet, "net.minecraft.network.protocol.game.ClientboundSetTimePacket") then
        strix.main(function()
            strix.toast("Сервер прислал время", { tone = "info" })
        end)
    end
end)
```

В очереди может ждать до 4096 задач, дальше `strix.main` даёт ошибку.

## Как потоки делят скрипт

Переменные скрипта можно спокойно использовать из обработчиков на разных потоках: одновременно в скриптах идёт только один поток, поэтому `count += 1` не теряет значений. Это значит и другое: долгий обработчик держит все остальные скрипты и может задержать пакеты.

Если скрипты заняты другим потоком дольше 200 мс, событие пропускается: пакет обрабатывается как обычно, запись появляется в логе клиента. Так игра не зависнет, даже если потоки ждут друг друга.

Ошибка в обработчике на сетевом потоке пишется в консоль, пакет не отменяется, а модуль выключается на ближайшем тике.
